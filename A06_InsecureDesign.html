ShopCart — Password Reset Takeover Chain
Fictional e-commerce platform with 3 cascading design flaws enabling complete account takeover. No password knowledge required.
1. Request Reset → 2. Weak Token → 3. No Rate Limit → 4. Brute Force → 5. Takeover

FLAW 2

RESULT: Any email account can be compromised in under 10 seconds without knowing the password.
VULNERABLE CODE
Backend: routes/auth.py
Source code exhibiting all design flaws. Each vulnerability marked with VULN.
→ STEP 1: TOKEN GENERATION
# POST /api/reset/request
@app.route('/api/reset/request', methods=['POST'])
def request_reset():
    email = request.json.get('email')
    user  = db.query("SELECT * FROM users WHERE email=?", email)

    if user:
        # VULN 1: Only 4 digits = 10k possibilities
        token = str(random.randint(1000, 9999))

        # VULN 2: Zero expiry — valid FOREVER
        db.execute("UPDATE users SET reset_token=?", token)

        send_email(email, f"Code: {token}")

    return {"status": "ok"}
→ STEP 2: TOKEN VERIFICATION
# POST /api/reset/verify
@app.route('/api/reset/verify', methods=['POST'])
def verify_token():
    email = request.json.get('email')
    token = request.json.get('token')

    # VULN 3: No rate limit — unlimited attempts/sec

    user = db.query("WHERE email=? AND reset_token=?", email, token)

    if user:
        # VULN 4: Token NEVER cleared after use
        reset_url = generate_signed_url(user.id)
        return {"status": "ok", "reset_url": reset_url}

    return {"status": "invalid"}

● FLAW 1: random.randint() is NOT cryptographically secure. Only 9,000 possible values. Brute-force time: ~5 seconds.

● FLAW 2: No expiry timestamp stored. Token remains valid indefinitely, even days later.

● FLAW 3: Zero throttling on /verify endpoint. Attacker submits 10,000 attempts per second unobstructed.

● FLAW 4: Token is never deleted after first use. Same token can be reused by attacker after victim resets password.

Backend: routes/auth.py (SECURED)
All 4 flaws mitigated. Each fix marked with FIX.
→ STEP 1: SECURE TOKEN GENERATION
# FIX: Rate limit decorator — 3 resets/hour per email
@rate_limit(max=3, window="1h", key="email")
@app.route('/api/reset/request', methods=['POST'])
def request_reset():
    # FIX 1: 256-bit cryptographically secure token
    token = secrets.token_urlsafe(32)

    # FIX 2: 15-minute expiry enforced server-side
    expires_at = datetime.utcnow() + timedelta(minutes=15)
    db.execute("UPDATE users SET reset_token=?,
                token_expires=?", token, expires_at)

    return {"status": "ok"}
→ STEP 2: RATE-LIMITED VERIFICATION
# FIX 3: Rate limit — max 5 attempts per 10 min per IP
@rate_limit(max=5, window="10m", key="ip")
@app.route('/api/reset/verify', methods=['POST'])
def verify_token():
    user = db.query("WHERE email=? AND reset_token=?
                     AND token_expires > ?",  # Check expiry
                    email, token, datetime.utcnow())

    if user:
        # FIX 4: Invalidate token immediately after use
        db.execute("UPDATE users SET reset_token=NULL,
                    token_expires=NULL WHERE id=?", user.id)
        return {"status": "ok"}

● FIX 1: secrets.token_urlsafe(32) generates 256 bits of cryptographic entropy. Brute-force time: 2^128 years.

● FIX 2: Token expires in 15 minutes. Even if leaked, the attack window is tiny.

● FIX 3: Rate limiting makes brute-force require 2,000+ hours at 5 attempts per 10 minutes.

● FIX 4: Single-use enforcement — token deleted immediately. Replayed tokens return "invalid".
